List guidelines

How models get placed, how points are awarded, and what counts as a record.

What the list is

The Model List is a ranked ordering of general-purpose language models by frontier capability. Position #1 is the strongest model available to the public. The list is editorial: placements are decided by the list team from independent benchmark runs, blind-preference arenas, and hands-on agentic testing, then argued about in public.

The three tiers

  • Main list (#1–#15). Current frontier. Full list points.
  • Extended list (#16–#30). Still competitive, usually a generation behind or a smaller tier of a main-list family. Reduced points.
  • Legacy list (#31+). Kept for history. No points. Models never leave the site once placed.

Placement rules

  1. A model must be callable by the public through an API or downloadable weights. Invitation-only models are listed but flagged, and score no points until access opens.
  2. One entry per model. Reasoning modes, effort levels, and "thinking" variants are settings, not separate models.
  3. Preview and experimental checkpoints are placed only if the lab publishes pricing and a model ID.
  4. Vendor-reported numbers are shown with a red tag. They never move a model up on their own. An independent or community re-run under a public harness is required.
  5. A model that is deprecated or removed from the API drops to legacy on the next update.

List points

Points fall off steeply with position, so a model at #1 is worth roughly five times one at #15. A lab's score is the sum of its models' points.

main list, p = 1…15:   pts(p) = 250 · 0.888(p − 1)
extended, p = 16…30:  pts(p) = 50 · (31 − p) / 16
legacy, p ≥ 31:         pts(p) = 0

What counts as a record

A record is a benchmark result attached to a model. Submit one from the Submit tab. To be accepted it needs a public source page, the harness type, and a score with its unit. Reviewers check the run configuration against the benchmark's rules before it appears on the model's page.
